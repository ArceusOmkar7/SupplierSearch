## Typed boundary

Country packs implement these operations through backend interfaces, not public buyer endpoints:

| Operation | Input | Output / restriction |
|---|---|---|
| capabilities | jurisdiction, free source/dataset versions, optional free-project quota | Supported claims/identifiers, disabled reasons and provenance/freshness/access policy. No invented enabled source or mandatory paid entitlement. |
| plan_checks | confirmed requirements, supplier/site identities, confirmed claims, run budgets | Independent typed check tasks/dependencies with candidate sources. No requirement edits, verdicts or messages. |
| normalize_identity | original name/IDs/addresses with role | Normalized candidates plus preserved originals and discrepancy reasons. Fuzzy score is a suggestion. |
| execute_check | task ID, immutable run/revision/checklist context, source policy, reserved budget | Actual attempts and retrieved observations/artifacts, or explicit no-evidence result. No buyer CAPTCHA/portal task. |
| interpret_regulation | confirmed product, jurisdiction/date, official document version set | Proposed applicability/standard/site requirements with exact cited order/exemption/date basis or unresolved gaps. Shared policy validates publication. |
| warning_patterns | observations with identity/site/time context | Attributable review indicators; no conclusive verdict from indicators alone. |

Every envelope contains case_id, run_id, revision_id, checklist_id, supplier_id, optional site_id, country_pack/version, policy_version, operation_key and write_generation. Returned references must resolve within that case. Shared storage/authorization/budget clients are injected; packs cannot bypass them or supply an owner_id.

Pack registration is an explicit configuration registry, not arbitrary import of downloaded code. India is registered as `IN/core-v1`. Unsupported jurisdiction/claim types yield not_supported with visible coverage. Country-boundary validation uses attributable real records from both jurisdictions to check the shared envelope; actual US checking belongs to008. No invented country-pack results.

## Check result envelope

Result fields: task_id, processing_state, attempt_ids, observations, artifact_ids, missing_fields, coverage_gaps, identity_candidates and optional dependent_action. Each observation carries source definition/version, URL/document/page locator, actual content excerpt/observation, collection time, available issue/effective/expiry dates, self_reported, authority_role and origin_lineage.

Each attempt explicitly identifies kind (capability/remote/document/deadline), target, request_dispatched, start/finish, outcome and reason. A configuration check can be an actual local attempt while stating that no external lookup occurred. Never create evidence from an empty response, timeout, disabled source or planned-but-unsent request. Retries link to their predecessor; uncertain external outcomes are preserved.

Source outcome semantics:

- success: actual content retrieved; still subject to identity/freshness/criteria validation.
- no_record: no matching result; not proof of nonexistence or counterfeit status.
- blocked/unavailable: exact CAPTCHA/authorization/permission/configuration/consent reason, automatic eligible alternatives, then unproven gaps.
- timeout/transient_error: bounded retry within source and run deadlines; honor valid Retry-After or stop.
- skipped: missing identifier/budget/deadline/unsupported coverage; disclose that no remote lookup occurred.

Locked buyer-uploaded documents can request a replacement/unlocked upload. Identity ambiguity can request buyer review. These actions pause only dependent work. Downloaded documents and external portal failures do not request manual scraping. No passwords, CAPTCHA workarounds or supplier contact are generated by the pack.

## Free-source, local-import and model contract

The local product requires zero paid keys or cloud services. Required adapters are permitted public-page/document fetching, actual local official-export lookup, real eligible issuer records and local model extraction. Optional Gemini free-tier calls require current free-model/project eligibility and actual quota, never a billing-enabled fallback. IAF/Sandbox/FinAGG/Cashfree or paid Search grounding are not implementation/acceptance prerequisites and no premium purchase is prompted when free coverage is missing.

Each source records allowed operations/hosts, access/reuse policy/check date, claim coverage and original/publication/collection dates. Free sources need no tariff configuration. Robots allowance is distinct from reuse rights; no CAPTCHA bypass or prohibited IndiaMART fetching. A blocked source tries eligible free alternatives and then records an honest evidence gap. Lack of current free GST/BIS status access remains unproven.

`import_source` is operator-local tooling, not an arbitrary-path buyer API. Input is an actual legitimately obtained CSV/XLSX/PDF/HTML file plus manifest: publisher, original official URL, licence/attribution, obtained time, publication/cutoff, geographic/entity coverage, original SHA256 and schema/import version. Output is a validated dataset ID, actual imported/quarantined row counts, schema issues and source coverage. Never invent missing rows/fields or substitute a demo dataset when download fails. Operator-obtained exports may require a one-time legitimate portal login; buyer verification still performs local checks automatically without per-run manual lookup.

`lookup_source` accepts exact supplier identifiers and dataset versions and returns matching original row/page references, observed business fields, cutoff and gaps. A file imported today cannot prove current status from an old cutoff. Imported source corpus supports known-supplier verification only; feature003 owns general discovery/indexing. Exclude unnecessary personal/demographic fields from case views and free model inputs. Only authorized selected record copies become case evidence; raw global datasets are not exposed through buyer endpoints.

Inference input includes model configuration, data classification and source references. Unknown/private/confidential/personal inputs stay local. Eligible public business content may use configured Gemini free tier; scraped availability alone cannot waive the provider's personal-data restriction. Output is a proposed extraction with source locators and model/version metadata, never a trusted verdict. Local-model unavailability cannot silently send private data to cloud. Preserve all proof gates regardless of model.

Free project request/token quotas use shared atomic reservations tagged verification/discovery/monitoring;002 only dispatches verification. No numeric free quota is invented. Additional API keys cannot bypass a project limit. One local inference at a time,4K initial context, public-page limit20/supplier and five certificate PDFs/supplier, one/domain request, global4 requests,20-second timeout, one transient retry and15-minute website deadline. Respect tighter source/project limits. Quota exhaustion queues bounded work or returns an explicit unavailable check; paid spending remains disabled.

Data in the application/evaluation corpus must be actual real-world records with provenance. Faithful captured-response replay is labeled with original URL/date/hash and replay condition. Controlled failures/restarts/clock changes exercise system behavior using those real records; never fabricate an official response, certificate status, evidence excerpt or supplier. No synthetic country pack, seeded demo supplier or invented auditor label is an acceptable substitute for missing real material.

## Publication policy

The shared policy service accepts proposed semantic mappings, never a ready-made trusted verdict from a source or model. Validate:

1. Claim and criterion were explicitly confirmed for this revision/checklist.
2. Referenced evidence/attempts exist and belong to this case/supplier.
3. Evidence addresses the assertion and relevant entity/site/period, preserving unresolved conflicts.
4. Required source authority and independent origin lineages are present; self-reported or copied supplier text is not independent proof.
5. Current status checks and documentary period coverage satisfy freshness; missing dates remain gaps.
6. Every required criterion/subclaim is satisfied for proven, or qualifying direct refutation establishes contradicted. Otherwise publish unproven with inspectable reasons/remaining evidence.

Claim-type checks:

| Claim type | Publication minimum |
|---|---|
| Legal existence/active status | Matching official current-run registry result or voluntarily provided attributable official result under policy; no manual-result prerequisite. |
| Manufacturer | Relevant production-site evidence plus independent attributable corroboration of that activity/site. Registry activity alone is insufficient. |
| Part capability | Each required material/process/tolerance/volume subclaim covered and independently corroborated by relevant production/inspection/buyer records. |
| Certificate validity/accreditation/scope/site | Separate matched authoritative status, relevant accreditation, standard/date/scope/site evidence. NABCB issuer accreditation alone cannot validate the supplier certificate. |
| Regulatory compliance | Current official order/applicability/date/exemption basis; where required, matching current official licence covering product/site. Missing catalog hit or blocked licence lookup is insufficient. |
| Capacity plausibility | Dated site/process/output records and independent corroboration for required volume/period. Headcount/machine counts alone cannot prove it. |

Evidence validators are deliberately conservative. Structured model output can still be semantically wrong; ambiguous coverage remains unproven. Preserve candidate reasoning and original records for auditor review. No model response can manufacture a citation, confirm identity, authorize a fetch or change proof thresholds. Audit evaluation must include schema-valid but substantively unsupported model proposals.

Assessment writes append history. Compound proven requires every required child proven; qualifying refutation of a required child yields contradicted, otherwise unproven. Processing status is orthogonal to verdict. A deadline snapshot evaluates every confirmed claim from actual available observations/attempts and exposes unscheduled/pending checks without pretending external checks ran.

Qualified list = suppliers with all buyer-required claims proven. Follow-up list = at least one required unproven and no required contradicted. Required contradicted excludes both; reasons remain visible. No required claims selected blocks run admission. Optional claims remain visible, and buyer selection remains an explicit separate decision.

## Shared extension seams

- Discovery003 hands off buyer-curated supplier identifiers to a draft revision and consumes owner/identity/source-budget rules; it never starts verification without core confirmation.
- PDF004 and voice006 supply field drafts with provenance/uncertainty, not confirmed values. Core retains editability and explicit confirmation.
- Outreach005 attaches messages/reply evidence to the owning case/revision with deduplication and core certificate processing. Core002 contains no send behavior; each future send needs exact buyer approval.
- Monitoring007 reuses identities, evidence policy and shared source budgets; it cannot silently rewrite closed assessments or recreate deleted cases.
- Country008 registers another pack returning the same envelope; it cannot redefine verdicts or core case storage.

All extension writes use case ownership, current generation and deletion fences. Duplicate operation keys cannot create duplicate evidence/events. Later revisions do not inherit earlier verdicts as current proof; evidence reuse is explicitly revalidated. Deletion cancellation/ledger semantics apply across future work.
